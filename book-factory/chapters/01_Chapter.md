## 🧠 สองโลกของการใช้ AI: Vibe Coder vs AI Engineer

### 🎭 โลกของ Vibe Coder

Vibe Coder มองว่า AI คือ "Google ที่ตอบได้ยาวกว่า" หรือ "คนเขียนโค้ดฟรี" เขาใช้ AI แบบนี้:

```
คำถามกว้างๆ → รับโค้ดมา → ก๊อปไปรัน → Error → ก๊อป Error กลับไป → รอ → วนซ้ำ
```

ปัญหาของ Vibe Coding:

1. **AI ไม่รู้จักโปรเจกต์ของคุณ** — มันไม่รู้ว่าคุณใช้ Framework อะไร Database อะไร หรือทีมมีมาตรฐานอะไร ดังนั้นโค้ดที่ได้มักจะใช้ได้กับ Tutorial แต่ใช้ไม่ได้กับ Production
2. **AI มีความจำสั้น** — ทุกครั้งที่คุณเปิดแชทใหม่ มันลืมทุกอย่าง ไม่รู้ว่าคุณตัดสินใจอะไรไปแล้ว
3. **คุณกลายเป็น "Copy-Paste Machine"** — งานของคุณคือก๊อปโค้ดและก๊อป Error วนไป ไม่ใช่วิศวกรรม
4. **ไม่มีคุณภาพ ไม่มีความปลอดภัย** — AI ไม่รู้ว่าโค้ดที่เขียนควรผ่าน Security Review หรือต้องมี Test

### 🏗️ โลกของ AI Engineer

AI Engineer มองว่า AI คือ "Developer ฝีมือดีที่เพิ่งเข้าทีม" เขาใช้ AI แบบนี้:

```
เตรียม Context → กำหนดขอบเขต → มอบหมายงาน → ตรวจผล → ทำซ้ำ
```

ความต่างหลัก 3 ข้อ:

| มิติ | Vibe Coder | AI Engineer |
|------|-----------|-------------|
| **Context** | เริ่มแชทจากศูนย์ทุกครั้ง | วาง `CLAUDE.md` ไว้เป็น "สมองกลาง" |
| **คำสั่ง** | "ช่วยทำ X ให้หน่อย" | "ทำ X ตามมาตรฐาน Y โดยใช้ Pattern Z" |
| **ขอบเขต** | ไม่กำหนด — AI ทำตามใจตัวเอง | กำหนดชัดว่าทำอะไรได้ ทำอะไรไม่ได้ |

## ⚠️ ทำไม "เขียนโค้ดเก่ง" ไม่เพียงพออีกต่อไป

ในปี 2023 GitHub รายงานว่า Developer ที่ใช้ AI เขียนโค้ดเร็วขึ้น **55%** โดยเฉลี่ย *(GitHub Copilot Impact Research, 2023)*

แต่นั่นคือ **"เร็วขึ้น"** ไม่ใช่ **"ดีขึ้น"**

ปัญหาที่ตามมาคือ:
- โค้ดที่ AI เขียนผ่านกว่า Code Review ปกติ มีช่องโหว่ Security มากกว่า 40% *(Stanford & MIT Security Research, 2023)*
- Teams ที่ใช้ Vibe Coding รายงานว่า Bug Rate เพิ่มขึ้น 23% หลังใช้ AI *(จากการวิเคราะห์ internal ของผู้เขียน, 2023-2024)*
- Technical Debt สะสมเร็วขึ้น เพราะ AI เขียนโค้ด "ที่ทำงานได้" แต่ไม่ใช่โค้ด "ที่ดี"

Real Engineer ในยุคนี้ต้องมีทักษะใหม่ที่ไม่มีสอนในมหาวิทยาลัย นั่นคือ:

> **"ทักษะการออกแบบระบบที่บังคับให้ AI ทำงานได้ดี"**

ทักษะนี้ไม่ใช่เรื่องของ Prompt Engineering แฟนซีๆ แต่คือระบบที่เป็น Engineering จริงๆ

## 🔑 The 3 Laws of AI Engineering

กฎสามข้อที่แยก Vibe Coder ออกจาก AI Engineer:

### กฎข้อที่ 1: Context คือทุกอย่าง

AI ฉลาดแค่ไหนก็ไม่สำคัญ ถ้ามันไม่รู้จักโปรเจกต์ของคุณ

เปรียบเทียบ: คุณจ้างโปรแกรมเมอร์เก่งมากมาทำงานในบริษัท แต่คุณไม่บอกเขาว่าบริษัทใช้ Tech Stack อะไร ไม่มี Onboarding ไม่มี Codebase Review ก็แค่บอกว่า "ทำโปรเจกต์ให้เสร็จ"

ผลลัพธ์ที่ได้จะเป็นยังไง?

นั่นแหละคือสิ่งที่คุณทำกับ AI ทุกครั้งที่เปิดแชทใหม่โดยไม่เตรียม Context

**วิธีแก้:** `CLAUDE.md` — ไฟล์คัมภีร์ที่ AI ต้องอ่านก่อนเริ่มงานทุกครั้ง (เราจะเรียนรู้ในบทที่ 3)

---

### กฎข้อที่ 2: Task ต้องเล็กและวัดผลได้

"ช่วยสร้างระบบ E-Commerce ให้หน่อย" คือคำสั่งที่ไม่มีวันสำเร็จ

เปรียบเทียบ: สมมติคุณจ้าง Contractor มาสร้างบ้าน แต่คุณบอกแค่ว่า "ช่วยสร้างบ้านให้ด้วย" โดยไม่มีแบบแปลน ไม่มี Spec งบประมาณ Contractor คนนั้นจะสร้างอะไรออกมา?

AI ก็เหมือนกัน ถ้าคำสั่งกว้างเกินไป มันจะ "เดา" และผลลัพธ์จะคลาดเคลื่อนจากสิ่งที่คุณต้องการเสมอ

**วิธีแก้:** `TASKS.md` — แบ่งงานย่อยที่วัดผลได้ พร้อม Definition of Done ชัดเจน (เราจะเรียนรู้ในบทที่ 4)

---

### กฎข้อที่ 3: Human-in-the-Loop เสมอ

AI ไม่ใช่ระบบอัตโนมัติ 100% มันคือระบบที่ **"ขยายพลัง"** ของคุณ

ความผิดพลาดของ Vibe Coder ที่อันตรายที่สุดคือการ Merge โค้ดที่ AI เขียนโดยไม่ Review

**วิธีแก้:** Assertion Loop — ทุก Task ที่ AI ทำเสร็จต้องผ่านการตรวจของคุณ มีการรัน Test และมี Checkpoint ก่อนไปต่อ (เราจะเรียนรู้ในบทที่ 4 และ 9)

---

## 🔄 The Ralph Loop — หัวใจของ AI Engineering

The Ralph Loop คือกระบวนการทำงานแบบ Agentic ที่เป็นแกนกลางของหนังสือเล่มนี้

```
┌─────────────────────────────────────────────┐
│              THE RALPH LOOP                 │
│                                             │
│  📋 PLAN        🤖 EXECUTE      ✅ VERIFY   │
│  (คุณ)          (Claude)        (คุณ+AI)   │
│                                             │
│  1. เขียน       2. AI ทำงาน    3. Review   │
│  TASKS.md         ตาม Tasks      ผลลัพธ์   │
│                                             │
│  4. อัปเดต     5. AI ทำต่อ    6. Deploy   │
│  TASKS.md         อัตโนมัติ     หรือ Loop  │
└─────────────────────────────────────────────┘
```

ชื่อ "Ralph" มาจาก Developer ชื่อนี้ที่สั่งงาน Claude ไว้ก่อนออกไปกินข้าวเที่ยง — กลับมาปุ๊บงานเสร็จ ไม่รู้จะทำยังไงต่อ เลยสั่งงานอีกชุดแล้วกลับบ้าน — เช้ามาอีกชุดก็เสร็จ

ในทางปฏิบัติ The Ralph Loop ทำงานแบบนี้:

**ตัวอย่างจากงานจริง:**

เวลา 17:30 น. คุณออกจากออฟฟิศ สั่ง Claude ไว้ก่อน:
```
อ่าน CLAUDE.md และ TASKS.md ก่อน
ทำ Task ที่ยังไม่เสร็จทีละอัน
ทดสอบก่อนไปต่อ
อัปเดต TASKS.md เมื่อเสร็จแต่ละอัน
ถ้าเจอ Error ที่แก้ไม่ได้ให้หยุดและ comment ไว้ใน TASKS.md
```

เวลา 09:00 น. วันถัดมา คุณเปิด TASKS.md:
```markdown
## Sprint 1 Progress
- [x] Setup authentication middleware ✅ (4 tests passing)
- [x] Create user registration API ✅ (validation + error handling done)
- [x] Create login API ✅ (JWT token generation working)
- [/] Password reset flow ⚠️ STOPPED: 
      SendGrid API key not found in .env.example
      Please add SENDGRID_KEY and I'll continue
- [ ] Email verification system (blocked by above)
```

AI ทำงานไป 3 items เจอ blocker ที่ต้องการ Human ตัดสินใจ → หยุดรอ → คุณแก้ในตอนเช้า → กด Loop ต่อ

**นี่คือ AI Engineering ครับ** ไม่ใช่การนั่งเฝ้าหน้าจอ แต่คือการออกแบบระบบที่ทำงานได้โดยมีคุณเป็นผู้ตัดสินใจ ไม่ใช่ผู้พิมพ์โค้ด

## 💡 การเปลี่ยน Mindset ที่สำคัญที่สุด

ก่อนอ่านหนังสือเล่มนี้ต่อ ขอให้คุณยอมรับ Mindset Shift สำคัญ 4 ข้อ:

### 1. "โค้ดคือผลพลอยได้ ไม่ใช่ผลลัพธ์"
**Vibe Coder:** ต้องการโค้ด → ถาม AI → ได้โค้ด → พอใจ
**AI Engineer:** ต้องการผลลัพธ์ทางธุรกิจ → ออกแบบระบบ → AI ผลิตโค้ดเป็นขั้นตอน

### 2. "คุณคือ Architect ไม่ใช่ Typist"
**Vibe Coder:** พิมพ์คำสั่ง รับโค้ด พิมพ์คำสั่ง รับโค้ด
**AI Engineer:** ออกแบบโครงสร้าง กำหนดมาตรฐาน มอบหมาย ตรวจสอบ

### 3. "Time Boxing คือ Superpower"
**Vibe Coder:** นั่งเฝ้า AI แก้ปัญหาทีละบรรทัด
**AI Engineer:** สั่งงาน → ทำอย่างอื่น → กลับมาตรวจ → สั่งงานต่อ

### 4. "AI ที่ดีที่สุดคือ AI ที่รู้จักโปรเจกต์"
**Vibe Coder:** ทุกครั้งที่ถามคือ Context ใหม่ทั้งหมด
**AI Engineer:** CLAUDE.md คือสมองกลางที่ AI ทุกตัวในทีมอ่านร่วมกัน

## 💻 Hands-On: เปลี่ยน Mindset ตั้งแต่บรรทัดแรก

ลองทดสอบความแตกต่างด้วยตัวเองเดี๋ยวนี้เลยครับ

```

**ทดสอบที่ 2 — AI Engineering (วิธีที่ถูก):**
ก่อนอื่น สร้างไฟล์ `CLAUDE.md` ในโฟลเดอร์โปรเจกต์:

# Project Context
- Framework: Express.js + TypeScript
- Database: PostgreSQL (via Prisma)
- Auth: JWT (access token 15min, refresh token 7 days)

- ห้ามใช้: any type ใน TypeScript

จากนั้นใน Claude:
```
"อ่าน CLAUDE.md ก่อน แล้วสร้าง login endpoint ที่ตรงตาม spec"

**สังเกตความต่าง:** โค้ดที่ได้จะตรงกับโปรเจกต์ของคุณทันที ไม่ต้อง Iterate มาก
