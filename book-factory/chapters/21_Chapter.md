## 🔐 มิติที่ 1: Data Privacy — อะไรส่งได้ อะไรส่งไม่ได้

### ข้อมูลที่ **ห้ามส่ง** ไปยัง AI API โดยไม่มี Legal clearance

```
🚫 ข้อมูลส่วนบุคคลที่ระบุตัวตนได้ (PII — Personally Identifiable Information):
   ชื่อ-นามสกุลจริง + อีเมล/เบอร์โทร + เลขบัตรประชาชน
   ที่อยู่จริง + วันเกิด + รูปภาพใบหน้า

🚫 ข้อมูลทางการแพทย์ (PHI — Protected Health Information):
   ประวัติการรักษา + ผลตรวจเลือด + ชื่อยา + วินิจฉัยโรค

🚫 ข้อมูลทางการเงิน:
   หมายเลขบัตรเครดิต + รหัส CVV + เลขบัญชีธนาคาร

🚫 ข้อมูล Business Confidential:
   Source code ที่มี Trade Secret + เอกสารสัญญาลับ
   ข้อมูลลูกค้าที่ยังไม่ได้รับอนุญาต

🚫 ข้อมูลเด็กอายุต่ำกว่า 13 ปี (COPPA compliance)
```

### ข้อมูลที่ **ส่งได้** อย่างปลอดภัย

```
✅ ข้อมูล Anonymized (ลบ PII ออกแล้ว):
   "ลูกค้าอายุ 35-45 ปี ซื้อสินค้า X" ← ไม่มีชื่อ ไม่มีอีเมล

✅ ข้อมูล Synthetic (สร้างขึ้นมาเพื่อ test):
   Test data ที่ไม่ใช่ข้อมูลจริงของลูกค้าจริง

✅ Source code ที่ไม่มี secrets:
   Code logic, algorithms, architecture patterns

✅ เอกสารสาธารณะ:
   Documentation, public API specs, open-source code

✅ ข้อมูลรวม (Aggregated):
   "ยอดขายเฉลี่ยต่อเดือน 500,000 บาท" ไม่ใช่รายการแต่ละ transaction
```

### วิธี Anonymize ข้อมูลก่อนส่ง AI

```typescript
// src/utils/anonymizer.ts
interface RawCustomerData {
  name: string;
  email: string;
  phone: string;
  purchaseHistory: string;
  feedback: string;
}

interface AnonymizedData {
  customerId: string; // hash แทน PII
  purchaseHistory: string;
  feedback: string;
}

export function anonymizeForAI(data: RawCustomerData): AnonymizedData {
  const { createHash } = require('crypto');

  return {
    // แทนที่ PII ด้วย hash (reversible ใน internal system แต่ AI ไม่รู้)
    customerId: createHash('sha256')
      .update(data.email + process.env.HASH_SALT)
      .digest('hex')
      .slice(0, 8),

    // ลบข้อมูลส่วนตัวออก เก็บแค่ business data
    purchaseHistory: data.purchaseHistory
      .replace(/\b[A-Z][a-z]+ [A-Z][a-z]+\b/g, '[NAME]')  // ชื่อ
      .replace(/\b[\w.]+@[\w.]+\b/g, '[EMAIL]')              // email
      .replace(/\b0[0-9]{9}\b/g, '[PHONE]'),                 // เบอร์โทร

    feedback: data.feedback,
  };
}

// ใช้งาน
const raw = await db.getCustomer(customerId);
const safe = anonymizeForAI(raw);          // ← Anonymize ก่อน
const analysis = await claude.analyze(safe); // ← ส่ง AI เฉพาะส่วนที่ safe
```

## ©️ มิติที่ 2: IP & Copyright — โค้ดที่ AI เขียน ใครเป็นเจ้าของ

นี่คือคำถามที่ Legal teams ถามมากที่สุดครับ

### สถานะปัจจุบัน (2025)

```
ประเทศส่วนใหญ่รวมถึงไทย:
- ลิขสิทธิ์ต้องมีผู้สร้างที่เป็นมนุษย์
- โค้ดที่ AI สร้าง 100% โดยไม่มี human contribution
  อาจไม่ได้รับการคุ้มครองลิขสิทธิ์

- โค้ดที่มนุษย์ review, แก้ไข, และ integrate
  มีแนวโน้มได้รับการคุ้มครอง

Anthropic Terms of Service (Claude):
- Output ที่ได้จาก Claude เป็นของ User
- Anthropic ไม่อ้างสิทธิ์ใน Output
- แต่ไม่มี indemnification สำหรับ IP claims
```

### แนวปฏิบัติที่ปลอดภัย

```markdown
# IP Protection Checklist สำหรับ AI-generated code

✅ DO: Human-in-the-Loop Review
   ให้ Developer review, แก้ไข, และ integrate code ทุกชิ้น
   → สร้าง "human authorship element" ที่ชัดเจน

✅ DO: Document AI contribution
   ใส่ comment ว่าส่วนไหน AI-generated และ human-reviewed:
   // Generated by Claude, reviewed and modified by [ชื่อ] on [วันที่]

✅ DO: ตรวจสอบ third-party code
   AI อาจ reproduce copyrighted code จาก training data
   ใช้ tools: GitHub Copilot Detect, OpenAI Content Filter

✅ DO: ใช้ Enterprise Plan
   Anthropic Enterprise Plan มี zero data retention
   และ terms ที่ชัดเจนกว่าเรื่อง IP

❌ DON'T: Copy code จาก AI โดยไม่ review
❌ DON'T: Claim AI-generated code เป็น original work ใน patent
❌ DON'T: ส่ง competitor's code ให้ AI วิเคราะห์ (trade secret risk)
```

## 📋 มิติที่ 3: PDPA & GDPR — กฎหมายที่ต้องรู้

### PDPA (Personal Data Protection Act) — ไทย

```
พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562

ข้อมูลส่วนบุคคล = ข้อมูลที่ระบุตัวตนได้ เช่น ชื่อ, เลขบัตร, อีเมล

การส่งข้อมูลส่วนบุคคลให้ Third-party (รวมถึง AI API):
→ ต้องมีฐานทางกฎหมาย (Legal Basis) ข้อใดข้อหนึ่ง:
   1. ความยินยอม (Consent) จากเจ้าของข้อมูล
   2. การปฏิบัติตามสัญญา
   3. ประโยชน์สาธารณะ
   4. ประโยชน์อันชอบธรรม (Legitimate Interest)
   5. ภาระผูกพันตามกฎหมาย
   6. เพื่อปกป้องชีวิต

→ ต้องมี Data Processing Agreement (DPA) กับ Third-party
→ ต้องแจ้ง Privacy Notice ให้ Data Subject รับทราบ
```

### Checklist สำหรับ AI ในระบบที่มี PDPA

```markdown
## PDPA Compliance Checklist — AI Projects

### ก่อน Deploy AI Feature
- [ ] ระบุว่าข้อมูลส่วนบุคคลอะไรที่จะส่งให้ AI
- [ ] มี Legal Basis อะไรสำหรับการประมวลผล?
- [ ] ทำ Data Privacy Impact Assessment (DPIA)
- [ ] ลงนาม DPA กับ Anthropic (Enterprise Plan)
- [ ] อัปเดต Privacy Notice ของบริษัท

### ระหว่างใช้งาน
- [ ] Log ว่าข้อมูลอะไรถูกส่งให้ AI เมื่อไหร่
- [ ] มีกลไก Data Subject Rights (ขอลบ/แก้ไขข้อมูล)
- [ ] Retention policy: เก็บ logs นานแค่ไหน?

### กรณีที่ไม่แน่ใจ
→ ใช้ Anonymized หรือ Synthetic data แทน
→ ปรึกษา DPO (Data Protection Officer) ก่อน
```

## 🤖 มิติที่ 4: Responsible AI — ใช้อย่างไรไม่ให้เกิดความเสียหาย

### ปัญหาที่เกิดบ่อยในองค์กร

```
❌ AI Bias ใน HR Decisions
   ถ้าใช้ AI คัดกรอง resume → ต้องระวัง bias ต่อเพศ อายุ เชื้อชาติ
   Real Engineer ต้องมี human final decision เสมอ

❌ AI Hallucination ในงานที่ Critical
   Claude บางครั้งสร้างข้อมูลที่ดูน่าเชื่อถือแต่ผิด
   ห้ามใช้ AI output โดยตรงในเอกสารทางกฎหมาย ทางการแพทย์

❌ Over-reliance on AI
   Developer ที่ไม่ review code → production bug
   มี Human-in-the-Loop เสมอ

❌ Deepfake / Impersonation
   ห้ามสร้าง content ที่แกล้งทำเป็นว่ามาจากคนจริง
```

### Responsible AI Policy Template

```markdown
# [บริษัท] — AI Usage Policy v1.0
Effective: [วันที่]
Owner: CTO / Legal

## 1. ขอบเขตการใช้งาน AI
AI Tools ที่อนุมัติ: Claude Code, Claude API (Enterprise)
Use cases ที่อนุมัติ:
  ✅ Code generation และ review
  ✅ วิเคราะห์ข้อมูลที่ anonymized แล้ว
  ✅ Draft เอกสาร (ต้องมี human review ก่อน publish)

Use cases ที่ไม่อนุมัติ:
  ❌ ส่งข้อมูลลูกค้าจริงโดยไม่ Anonymize
  ❌ ตัดสินใจทาง HR, Legal, Medical โดยไม่มี human review
  ❌ สร้าง content ที่ impersonate บุคคลจริง

## 2. ข้อกำหนดด้านข้อมูล
- PII ต้อง Anonymize ก่อนส่ง AI เสมอ
- Source code ที่มี secrets ห้ามส่ง AI
- Financial data ต้อง aggregated เท่านั้น

## 3. Human Oversight Requirements
- AI-generated code: ต้อง Developer review ก่อน merge
- AI-generated content: ต้อง Editor review ก่อน publish
- AI-assisted decisions: มนุษย์ต้องเป็นผู้ตัดสินใจสุดท้าย

## 4. Logging & Audit
- Log ทุก AI API call ที่เกี่ยวกับข้อมูลลูกค้า
- Retention: 90 วัน
- Review: ทุก Quarter โดย Security Team

## 5. การฝึกอบรม
พนักงานที่ใช้ AI ต้องผ่าน:
- AI Ethics Training (1 ชั่วโมง ปีละครั้ง)
- Data Privacy Refresher (ครึ่งปีครั้ง)
```

## 💻 Hands-On: สร้าง AI Safety Layer

```typescript
// src/middleware/ai-safety.ts
// Middleware ที่ตรวจก่อนส่งข้อมูลให้ AI

interface SafetyCheckResult {
  safe: boolean;
  issues: string[];
  sanitized?: string;
}

const PII_PATTERNS = [
  { name: 'Thai ID Card',    regex: /\b[0-9]{13}\b/ },
  { name: 'Email',           regex: /\b[\w.]+@[\w.]+\.[a-z]{2,}\b/gi },
  { name: 'Thai Phone',      regex: /\b0[0-9]{9}\b/ },
  { name: 'Credit Card',     regex: /\b[0-9]{4}[\s-][0-9]{4}[\s-][0-9]{4}[\s-][0-9]{4}\b/ },
  { name: 'Thai Name',       regex: /(?:นาย|นาง|นางสาว|ด\.ช\.|ด\.ญ\.)\s+\S+\s+\S+/ },
];

const SENSITIVE_KEYWORDS = [
  'รหัสผ่าน', 'password', 'secret', 'api_key', 'private_key',
  'ผลตรวจเลือด', 'โรคมะเร็ง', 'HIV', 'ยาเสพติด',
];

export function checkAISafety(text: string): SafetyCheckResult {
  const issues: string[] = [];
  let sanitized = text;

  // ตรวจ PII patterns
  for (const pattern of PII_PATTERNS) {
    if (pattern.regex.test(text)) {
      issues.push(`Found potential ${pattern.name}`);
      sanitized = sanitized.replace(pattern.regex, `[${pattern.name.toUpperCase()}]`);
    }
  }

  // ตรวจ sensitive keywords
  for (const keyword of SENSITIVE_KEYWORDS) {
    if (text.toLowerCase().includes(keyword.toLowerCase())) {
      issues.push(`Contains sensitive keyword: ${keyword}`);
    }
  }

  return {
    safe: issues.length === 0,
    issues,
    sanitized: issues.length > 0 ? sanitized : undefined,
  };
}

// Express middleware
export function aiSafetyMiddleware(req, res, next) {
  const userInput = req.body.message || req.body.prompt || '';
  const check = checkAISafety(userInput);

  if (!check.safe) {
    // Option A: Block request
    // return res.status(400).json({ error: 'Input contains sensitive data', issues: check.issues });

    // Option B: Auto-sanitize and continue
    req.body.message = check.sanitized;
    req.aiSafetyWarnings = check.issues;

    // Log for audit
    logger.warn('AI Safety: Auto-sanitized input', {
      userId: req.user?.id,
      issues: check.issues,
      timestamp: new Date().toISOString(),
    });
  }

  next();
}
```
