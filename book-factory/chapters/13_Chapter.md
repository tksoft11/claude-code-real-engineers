## 🪝 วิศวกรที่เก่งที่สุด แต่ทำอะไรไม่ได้

นายเอก Senior Developer 6 ปี อ่านบทความเกี่ยวกับ Claude Code แล้วตื่นเต้นมาก เขาทดสอบที่บ้านและพบว่าสามารถทำงานได้เร็วขึ้น 3 เท่า

วันจันทร์ เขาเข้าไปคุยกับหัวหน้า:

> "ผมอยากใช้ Claude Code ในโปรเจกต์ครับ มันช่วยให้เขียนโค้ดเร็วขึ้นมากเลย"

หัวหน้าถามกลับว่า:
> "แล้วข้อมูลลูกค้าจะรั่วไหมถ้า AI อ่านโค้ด? ค่าใช้จ่ายเท่าไหร่? ถ้า AI เขียนโค้ดผิดแล้วระบบพัง ใครรับผิดชอบ? IT Security อนุมัติหรือยัง?"

เอกตอบไม่ได้สักข้อ ประชุมจบลงด้วยคำว่า "เดี๋ยวดูก่อนนะ" ซึ่งหมายความว่า "ไม่"

เอกรู้ว่า AI จะช่วยทีมได้มาก แต่เขาไม่รู้ **ภาษาของผู้บริหาร**

## 🧠 ทำไมผู้บริหารถึงกลัว AI (และไม่ใช่เพราะโง่)

Real Engineer ต้องเข้าใจว่าคนที่ "ปฏิเสธ AI" ไม่ได้โง่ เขาแค่มี **ความรับผิดชอบที่ต่างออกไป**

```
คุณมองเห็น:                หัวหน้ามองเห็น:
┌─────────────────┐        ┌────────────────────────────┐
```

ความกังวลเหล่านี้ **สมเหตุสมผลทั้งหมด** และ Real Engineer ต้องตอบได้ทุกข้อ

## 📊 Framework: The AI Business Case

### ขั้นตอนที่ 1: วัดปัญหาปัจจุบันก่อน

ก่อนจะเสนออะไร ต้องรู้ว่าตอนนี้เสียเวลาไปกับอะไรบ้าง:

```markdown
# AI Business Case — Pre-Survey (กรอกเองก่อน)

## เวลาที่ทีมใช้ต่อสัปดาห์ (โดยประมาณ)
- เขียนโค้ดใหม่: ______ ชั่วโมง
- Debug + Fix bugs: ______ ชั่วโมง
- เขียน documentation: ______ ชั่วโมง
- Code review: ______ ชั่วโมง
- ประชุม planning: ______ ชั่วโมง

## ปัญหาที่ซ้ำซาก (ที่ AI น่าจะช่วยได้)
- [ ] เขียน boilerplate ซ้ำๆ
- [ ] อธิบายโค้ดเดิมให้สมาชิกใหม่
- [ ] หา bug ที่ใช้เวลานาน
- [ ] เขียน test cases
- [ ] สร้าง API documentation

## ค่าเสียโอกาส (ถ้าทำ features เร็วขึ้น 2x)
- Feature ที่รอ queue อยู่: ______ features
- Revenue ที่สูญเสียจากความล่าช้า: ______ บาท/เดือน
```

### ขั้นตอนที่ 2: คำนวณ ROI แบบง่าย

```
ROI Calculation Template:

ทีม: 5 คน Developer
เงินเดือนเฉลี่ย: 60,000 บาท/เดือน
ชั่วโมงทำงาน: 160 ชั่วโมง/เดือน
ค่าต่อชั่วโมง: 60,000 / 160 = 375 บาท/ชั่วโมง

ถ้า AI ช่วยประหยัดได้ 20% ของเวลา:
= 160 × 20% = 32 ชั่วโมง/คน/เดือน
= 32 × 375 = 12,000 บาท/คน/เดือน
= 12,000 × 5 = 60,000 บาท/เดือน ← ค่าที่ประหยัดได้

ค่า Claude API (5 คน):
= ~$50/คน/เดือน × 5 = $250 = ~9,000 บาท/เดือน

ROI รายเดือน = 60,000 - 9,000 = 51,000 บาท กำไร
ROI % = (51,000 / 9,000) × 100 = 567%
```

## 🛡️ ตอบข้อกังวลแต่ละข้อ

### ข้อกังวลที่ 1: "ข้อมูลลูกค้าจะรั่วไหม?"

```
✅ คำตอบที่ถูกต้อง:

Claude Code ทำงานบน Terminal ของเรา ไม่ใช่ Cloud ของ Anthropic
โค้ดที่ส่งไปยัง API คือ context ของการสนทนา ไม่ใช่ Database dump

เราสามารถควบคุมได้ด้วย:
1. CLAUDE.md: "ห้ามส่งข้อมูล PII ของลูกค้าออกไป"
2. .claude/settings.json: ห้าม Claude อ่านไฟล์ที่มีข้อมูลจริง
3. ใช้ test data เสมอในการพัฒนา
4. Enterprise Plan: Anthropic ไม่ใช้ข้อมูลเพื่อ train model

Anthropic มี SOC 2 Type II certification และ GDPR compliance
(พร้อม documentation สำหรับ IT Security)
```

### ข้อกังวลที่ 2: "ค่าใช้จ่ายเท่าไหร่?"

```
✅ คำตอบที่ถูกต้อง:

เริ่มต้น Pilot 1 เดือน ด้วยงบประมาณที่ชัดเจน:
- 2 Developer × $50/เดือน = $100 (~3,600 บาท)
- มี Spend Limit ที่ตั้งได้ใน Console — ไม่มีทางเกินงบ
- จ่ายตามการใช้งานจริง ไม่ใช่ subscription

เทียบกับ SaaS Tools อื่น:
- Jira: $8.15/user/month
- GitHub Copilot: $19/user/month
- Claude Code: ~$50/user/month แต่ทำได้มากกว่ามาก
```

### ข้อกังวลที่ 3: "ถ้า AI เขียนโค้ดผิดแล้วระบบพัง?"

```
✅ คำตอบที่ถูกต้อง:

Real Engineer ไม่ Deploy โค้ดที่ AI เขียนโดยไม่ Review ครับ
กระบวนการเหมือนเดิมทุกอย่าง:

Developer (Human) → Code Review → QA Testing → Staging → Production

AI เป็นแค่ "เครื่องช่วยพิมพ์ที่ฉลาดขึ้น" ไม่ใช่ผู้ตัดสินใจ
ทุก commit ยังต้องผ่าน Human Approval เหมือนเดิม
```

### ข้อกังวลที่ 4: "PDPA มีปัญหาไหม?"

```
✅ คำตอบที่ถูกต้อง:

PDPA ควบคุมการเก็บและใช้ข้อมูลส่วนบุคคล ไม่ใช่เครื่องมือ
ที่นักพัฒนาใช้ในการเขียนโค้ด

เราสามารถ compliant ได้โดย:
1. ไม่ส่งข้อมูลส่วนบุคคลจริงไปยัง API (ใช้ test data)
2. มี Data Processing Agreement (DPA) กับ Anthropic
3. เอกสาร Privacy Policy ของ Anthropic ระบุชัดว่าไม่เก็บข้อมูล
   ของ Enterprise customers เพื่อ training

เราเตรียม DPA document ให้ Legal team review ได้เลย
```

## 🎯 The Pilot Program: วิธีขออนุมัติที่ได้ผลที่สุด

แทนที่จะขอ "ใช้ AI ในโปรเจกต์ทุกอัน" — ขอแบบ **"Pilot 30 วัน"**

```markdown
# AI Pilot Program Proposal

## สรุป Executive (ต้องอ่านได้ใน 30 วินาที)
เสนอทดลองใช้ Claude Code เป็นเวลา 30 วัน กับทีม 2 คน
งบประมาณ: ไม่เกิน 7,200 บาท (จาก License ที่หมดอายุ Jira ที่ไม่ได้ใช้)
เป้าหมาย: เพิ่มความเร็วในการพัฒนา 20% สำหรับโปรเจกต์ [ชื่อ]

## ขอบเขตของ Pilot
✅ ใช้ใน: [Project A] — development environment เท่านั้น
✅ ผู้เข้าร่วม: [ชื่อ Dev 1], [ชื่อ Dev 2]
❌ ไม่ใช้ใน: Production system, ข้อมูลลูกค้าจริง
❌ ไม่รวม: [Project B] และ [Project C] ที่มี sensitive data

## Security Controls ที่วางไว้แล้ว
- CLAUDE.md ที่ห้าม AI อ่านไฟล์ .env และข้อมูลจริง
- .claude/settings.json ที่จำกัด permission
- ไม่ใช้ข้อมูล production ในการทดสอบ
- Review code ทุก commit ตามกระบวนการเดิม

## วิธีวัดผล (Metrics ที่ชัดเจน)
- จำนวน Features ที่ส่งมอบในช่วง Pilot vs เดือนก่อน
- เวลาเฉลี่ยต่อ Feature (วัดจาก Jira)
- Bug Rate (จาก QA report)
- Developer Satisfaction Score (แบบสอบถามสั้นๆ)

## Timeline
- วันที่ 1-3: Setup + Training
- วันที่ 4-25: ทำงานปกติพร้อม AI
- วันที่ 26-30: รวบรวมข้อมูล + สรุป Report

## Go/No-Go Criteria
ถ้า Pilot สำเร็จ (metrics บรรลุเป้า): ขยายไปทั้งทีม
ถ้าล้มเหลว: หยุดได้ทันที ไม่มีค่าใช้จ่ายเพิ่ม

## สิ่งที่ขอ
[ ] อนุมัติงบ 7,200 บาท สำหรับ 30 วัน
[ ] อนุมัติให้ทีมใช้ Claude Code ในขอบเขตที่กำหนด
[ ] ประชุม Review ในวันที่ 15 และ 30
```

## 📈 วิธีนำเสนอ Pilot Results

หลังจาก Pilot 30 วัน ให้รายงานแบบนี้:

```markdown
# Pilot Results Report — Claude Code (30 วัน)

## Executive Summary
ทดลองใช้ Claude Code กับทีม 2 คน ใน [Project A] เป็นเวลา 30 วัน

## ผลลัพธ์ที่วัดได้

| Metric | เดือนก่อน Pilot | ช่วง Pilot | การเปลี่ยนแปลง |
|--------|----------------|-----------|----------------|
| Features ที่ส่ง | 8 | 13 | +62.5% ⬆️ |
| Bug Rate | 4.2/sprint | 2.8/sprint | -33% ⬇️ |
| เวลาต่อ Feature | 3.2 วัน | 2.1 วัน | -34% ⬇️ |
| Test Coverage | 45% | 67% | +49% ⬆️ |

## ค่าใช้จ่าย vs ผลประโยชน์

ค่าใช้จ่าย Pilot: 6,840 บาท (ต่ำกว่างบ 5%)

ผลประโยชน์ที่คำนวณได้:
- เวลาที่ประหยัดได้: 48 ชั่วโมง × 375 บาท/ชั่วโมง = 18,000 บาท
- Features เพิ่มขึ้น 5 features × มูลค่าเฉลี่ย = ประมาณ XX บาท

ROI = (18,000 - 6,840) / 6,840 = 163%

## Security Incidents
0 ครั้ง — ไม่มีการรั่วไหลของข้อมูลใดๆ

## Developer Feedback
"ประหยัดเวลา debug ได้มากที่สุด — Bug ที่ใช้เวลา 2 ชั่วโมงก่อน
 ตอนนี้ใช้เวลา 20-30 นาที" — [Dev 1]

"ช่วยมากในการเขียน test ที่ครอบคลุม — เพิ่ม coverage จาก 45 เป็น 67%
 โดยไม่ได้ใช้เวลาเพิ่มมากนัก" — [Dev 2]

## คำแนะนำ
✅ ขยายไปทั้งทีม (5 คน) ด้วยงบ 18,000 บาท/เดือน
   (คาดว่า ROI เพิ่มขึ้นเมื่อ scale เพราะ shared context)
```
